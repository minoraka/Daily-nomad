# Доска в стиле Jira — дизайн

Дата: 2026-11-28. Расширяет `2026-11-27-student-board-design.md`; всё, что здесь не изменено, остаётся как там.

## Зачем

Заказчик хочет, чтобы доска выглядела и работала как Jira (референс — `reference/jira-board.webp`, скриншот доски Jira «Teams in Space»; стиль — `reference/lms-*.webp`: колонки со счётчиками, насыщенные карточки с метками, приоритетом, оценкой, номером и аватаркой, поиск и быстрые фильтры), но оставалась в визуальном стиле LMS колледжа (тёмная/светлая тема, красный акцент, тот же сайдбар и топбар).

Главное функциональное изменение: **преподаватель теперь может назначать задачи студентам** и принимать их через проверку. Раньше преподаватель только смотрел, а каждый студент вёл только свои карточки.

## Цели

1. Преподаватель создаёт задачу и назначает её одному, нескольким или всем студентам потока.
2. Колонка «На проверке»; задачи преподавателя принимает только преподаватель.
3. Карточка как в Jira: метки, приоритет, оценка, дедлайн, номер, исполнитель, признак «от преподавателя», счётчик комментариев.
4. Комментарии к задаче.
5. Поиск и быстрые фильтры над доской.
6. Подробная карточка задачи (модалка) в стиле Jira.

## Не-цели

Спринты, бэклог, эпики, дорожки (swimlanes), типы задач (баг/история), уведомления, история изменений, вложения, назначение задач студентами друг другу, редактирование комментариев.

## Анти-цели

- Студент может закрыть («Готово») задачу преподавателя сам.
- Студент может переписать условие задачи преподавателя.
- Доска стала синей «как Jira» — стиль LMS обязателен.
- Сломались уже работающие вещи: личные задачи студента, перетаскивание, привязка задач к дейликам, стрик.

## Подходы

- **А. Расширить существующую модель `Task`** — **выбран заказчиком.** Одна доска, одна логика перетаскивания и порядка, привязка к дейликам работает для всех задач. Минус — права зависят от автора задачи.
- **Б. Отдельная модель «Задание» для задач преподавателя.** Личные задачи не трогаются, но две модели, два API, вдвое больше логики перетаскивания и привязки к дейликам. Отклонён.
- Замена `dnd-kit` на готовую канбан-библиотеку — отклонено: перетаскивание уже работает и покрыто тестами.

## Решения заказчика

- Назначает только преподаватель (вариант «А» из обсуждения); студенты по-прежнему заводят себе свои задачи.
- Колонки: *Планирую → В работе → На проверке → Готово*. Задачи преподавателя студент двигает до «На проверке»; дальше преподаватель переводит в «Готово» или возвращает в «В работе». Свои задачи студент двигает куда угодно.
- Поля карточки: номер, приоритет, оценка, дедлайн, метки, исполнитель (см. ниже). Тип задачи — не делаем.
- Поиск + быстрые фильтры «Мои», «От преподавателя», «Просроченные», «На проверке».
- Комментарии нужны.

## Данные

Изменения `Task` (миграция с переносом данных):

```
owner        FK User (student) — ИСПОЛНИТЕЛЬ: на чьей доске карточка (поле остаётся, смысл тот же)
created_by   FK User, PROTECT — кто создал: сам студент или преподаватель.
             Миграция: для существующих задач created_by = owner.
status       + "review" (На проверке). Порядок колонок: todo, in_progress, review, done.
priority     low | medium | high | critical, default medium
estimate     PositiveSmallInteger, null; допустимы 1, 2, 3, 5, 8
deadline     DateField, null
labels       JSONField list[str], default []; ≤ 5 меток, каждая 1–24 символа после trim,
             дубликаты (без учёта регистра) убираются
batch        UUID, null — общий для копий одной задачи, созданных преподавателем за раз
```

Вычисляемые поля в API:
- `key` = `"SB-{id}"`.
- `from_teacher` = `created_by.role == teacher`.
- `is_overdue` = `deadline < localdate() (Asia/Bishkek) и status != done`.
- `comments_count`.

Новая модель:

```
Comment
  task       FK Task CASCADE related_name="comments"
  author     FK User CASCADE
  text       TextField (1–2000 символов после trim)
  created_at
  ordering   created_at
```

## Права

Обозначения: *личная* задача — `created_by == owner`; *задача преподавателя* — `created_by.role == teacher`.

| Действие | Личная задача | Задача преподавателя |
|---|---|---|
| Видеть | все вошедшие | все вошедшие |
| Создать | студент себе (`POST /tasks/`) | любой преподаватель (`POST /tasks/assign/`) |
| Менять поля (название, описание, приоритет, оценка, дедлайн, метки) | исполнитель | любой преподаватель |
| Двигать по колонкам / менять порядок | исполнитель — в любую колонку | исполнитель — между todo / in_progress / review; **в done, из done и внутри done — нельзя (403)**, такая карточка в «Готово» не перетаскивается. Преподаватель — в любую колонку |
| Удалить | исполнитель | любой преподаватель |
| Комментировать | исполнитель и любой преподаватель | исполнитель и любой преподаватель |
| Удалить комментарий | автор комментария | автор комментария |

«Любой преподаватель», а не только автор задачи — у преподавателей нет потоков, и заменять коллегу на проверке нормально (решение исполнителя).

Преподаватель на чужие *личные* задачи студентов прав не получает (только смотреть и комментировать).

Если исполнитель меняет статус задачи преподавателя через `PATCH` — те же ограничения, что и для перемещения.

## API (изменения к `/api/`)

```
GET    tasks/?group=&owner=&status=      как раньше; новые поля в ответе
POST   tasks/                            только student; тело может содержать priority, estimate,
                                         deadline, labels; created_by = owner = текущий
POST   tasks/assign/                     только teacher. Тело: title, description?, priority?,
                                         estimate?, deadline?, labels?, и РОВНО ОДНО из:
                                           assignees: [user_id, ...]  (студенты; можно из разных потоков)
                                           group: id                  (все студенты потока на момент создания)
                                         Создаёт по копии на каждого студента (status todo, в конец колонки,
                                         общий batch). 201 → список созданных задач.
                                         400: пустой список / не студенты / ни одного студента в потоке.
PATCH  tasks/{id}/                       по таблице прав
DELETE tasks/{id}/                       по таблице прав
POST   tasks/{id}/move/                  {status, position} по таблице прав
GET    tasks/{id}/comments/              список, по времени
POST   tasks/{id}/comments/              {text}; по таблице прав
DELETE comments/{id}/                    только автор
```

Правка задачи преподавателем меняет только эту копию (не весь `batch`) — решение исполнителя; `batch` пока нужен только для будущего и для группировки в админке.

## Интерфейс

Стиль — LMS (существующие CSS-переменные, сайдбар, топбар), раскладка — Jira.

### Доска

```
ДОСКА
[🔍 Поиск по названию или SB-номеру]  [Мои] [От преподавателя] [Просроченные] [На проверке]
[Поток: ИС-21 ▾] [Все студенты ▾]                                         [+ Задача]

ПЛАНИРУЮ 5        В РАБОТЕ 3         НА ПРОВЕРКЕ 2       ГОТОВО 8
┌──────────────┐
│ Свёрстать    │
│ форму входа  │
│ [FRONTEND]   │
│ ⇈ 3  📅5 дек │
│ 💬2  SB-25 (АИ)│
└──────────────┘
```

- Колонки — 4, заголовок «НАЗВАНИЕ N» как в Jira; на узком экране колонки в одну ленту.
- Поиск — по подстроке названия (без учёта регистра) или по номеру (`SB-25`, `sb25`, `25`), фильтрует на клиенте уже загруженные карточки.
- Быстрые фильтры — переключатели-пилюли, комбинируются через «И»:
  - «Мои»: студент — `owner == я`; преподаватель — задачи преподавателей (`from_teacher`).
  - «От преподавателя»: `from_teacher`.
  - «Просроченные»: `is_overdue`.
  - «На проверке»: `status == review`.
  Для преподавателя «Мои» и «От преподавателя» совпадают — у преподавателя показывать только «От преподавателя».
- Счётчики в заголовках колонок — по отфильтрованным карточкам.
- Кнопка «+ Задача»: студенту — на своём потоке (создаёт личную), преподавателю — всегда (создаёт назначение).

### Карточка

- Название (жирное, переносится).
- Метки — цветные плашки капсом (цвет детерминированно из хэша текста, палитра 6–8 цветов, читаемая в обеих темах).
- Нижняя строка: иконка приоритета (lucide: `ChevronsUp` critical, `ChevronUp` high, `Equal` medium, `ChevronDown` low; цвета: critical/high — акцент, medium — warning, low — muted), оценка в кружке (если есть), дедлайн «📅 5 дек» (красный, если `is_overdue`), счётчик комментариев 💬 (если > 0), справа номер `SB-25` и аватар-инициалы исполнителя.
- Задача преподавателя: маленькая пометка (иконка `GraduationCap`) рядом с номером; тултип «От преподавателя: ФИО».
- Своя карточка (которую можно тащить) — красная полоса слева, как сейчас.

### Перетаскивание

- Студент тянет свои карточки; карточку преподавателя — только между первыми тремя колонками (дроп в «Готово» отклоняется без запроса к серверу, показывается подсказка «Задачу принимает преподаватель»).
- Преподаватель тянет только задачи преподавателей. Любой перенос назад из «На проверке» или «Готово» (в более раннюю колонку) — перетаскиванием или селектом статуса в модалке — открывает маленький диалог «Вернуть в работу» с полем «Комментарий (необязательно)»; если текст есть — создаётся комментарий, затем перемещение. Отмена диалога — карточка возвращается.

### Подробная карточка (модалка)

Две колонки (на узком экране — одна):
- Слева: `SB-25` и название, описание, затем «Комментарии» — лента (аватар, ФИО, роль, время «сегодня 14:05» / «5 дек 14:05», текст, «Удалить» у своих) и поле ввода внизу (если можно комментировать).
- Справа: статус (селект, с теми же правилами), исполнитель, автор («от преподавателя …» или «личная»), приоритет, оценка, дедлайн, метки.
- Поля редактируемы, если у пользователя есть право менять поля; иначе — только текст.
- Преподавателю на задаче в «На проверке» — две кнопки: «Принять» (→ done) и «Вернуть в работу» (тот же диалог с комментарием).
- Удалить — по правам.

### Создание задачи преподавателем

Модалка: название, описание, приоритет, оценка, дедлайн, метки; блок «Кому»: переключатель «Весь поток» (по выбранному потоку на доске) / «Выбрать студентов» (мультивыбор чипами по студентам текущего потока). После создания — тост/строка «Назначено N студентам».

### Остальное

- Чипы задач в дейликах показывают номер: `SB-25 Свёрстать форму`.
- Главная студента — без изменений (отдельных блоков для задач преподавателя не добавляем).
- Преподаватель: пункт меню «Доска» остаётся стартовым; меню без изменений.
- Все новые строки — во всех трёх языках (`ru/en/ky`), включая названия приоритетов и колонки «На проверке» (`На проверке` / `In review` / `Текшерүүдө`).
- `seed_demo`: добавить 3–4 задачи от `demo_teacher` на поток ИС-21 (с дедлайнами, одна просроченная, одна в «На проверке») и пару комментариев; метки и приоритеты у части демо-задач. Сид остаётся идемпотентным.

## Проверка

- Backend-тесты: миграция (`created_by` заполнен), назначение (assignees / group / ошибки 400 / студент → 403), права из таблицы (особенно: студент не может в done и из done задачи преподавателя, ни через move, ни через PATCH; не может менять поля задачи преподавателя; преподаватель не может менять личную задачу), комментарии (кто может писать/удалять), `is_overdue` около полуночи по Бишкеку, валидация меток и оценки.
- Frontend (Vitest): поиск по номеру/названию, комбинирование быстрых фильтров, цвет метки детерминирован, запрет дропа в «Готово» для задачи преподавателя у студента.
- E2E (Playwright): преподаватель назначает задачу потоку → студент видит её, двигает в «На проверке» → преподаватель возвращает с комментарием → студент видит комментарий → снова на проверку → преподаватель принимает.
- Визуально: доска в тёмной и светлой темах на ru/ky, сравнение с референсом Jira по раскладке и LMS по стилю.

## Решения исполнителя после ревью

- Перестановка задачи преподавателя внутри «Готово» студентом тоже запрещена (принятую задачу студент не трогает).
- Диалог «Вернуть в работу» открывается при любом переносе назад из «На проверке» или «Готово», а не только review → in_progress.

## Оставлено исполнителю

- Точная палитра меток, иконки, отступы.
- Формат времени комментариев.
- Как показывать ошибки 403 при перетаскивании (тост или строка над доской — как сейчас).
