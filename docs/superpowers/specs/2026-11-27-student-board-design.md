# Student Board — дизайн

Дата: 2026-11-27

## Зачем

Студенты колледжа сами фиксируют свой прогресс: ведут личные задачи на канбан-доске и каждый день пишут короткий отчёт — «дейлик». Всё это видно всем: другим студентам и преподавателям. Никто ничего не назначает, не проверяет и не оценивает — это открытый журнал работы, а не система контроля.

Внешне сайт должен выглядеть как LMS колледжа (скриншоты заказчика: `reference/lms-home.webp`, `reference/lms-study.webp`): тёмный интерфейс, боковое меню слева с красной (#FF2D55-подобной) подсветкой активного пункта, верхняя панель с именем справа, контент — узкая колонка (~680px) по центру из скруглённых тёмных карточек, мелкий жирный шрифт, вкладки-«пилюли».

## Цели

- Личная канбан-доска студента: колонки *Планирую → В работе → Готово*, перетаскивание карточек.
- Общая доска потока: все карточки всех студентов потока, фильтр по студенту.
- Дейлики: один в день на студента, лента дейликов потока, привязка к карточкам.
- Стрик: сколько дней подряд студент пишет дейлики.
- Потоки (группы): у каждого потока своя доска и лента; переключатель потоков.
- Светлая и тёмная темы.
- Языки: русский, английский, кыргызский.

## Не-цели

- Задания от преподавателя, дедлайны, проверка, оценки.
- XP, монеты, уровни, любая геймификация кроме стрика.
- Чаты, расписание, тесты, материалы, новости (есть в оригинальной LMS — сюда не переносим).
- Комментарии, лайки, уведомления.
- Вход через соцсети/почту, восстановление пароля.

## Анти-цели (провал, даже если «работает»)

- Студент может менять чужие карточки или дейлики.
- Интерфейс заметно отличается по стилю от скриншотов LMS.
- Половина интерфейса не переведена или ломается в светлой теме.

## Подходы

Рассмотрены:

- **А. Раздельные frontend (React + Vite) и backend (Django REST), вход по JWT.** — **Выбран заказчиком.** Классическая схема, понятна для защиты, фронт и бэк независимы. Минус — чуть больше кода авторизации и CORS.
- **Б. Django раздаёт собранный React, сессионная авторизация.** Проще авторизация и деплой, но фронт и бэк связаны.
- Next.js и прочие фреймворки отброшены — заказчик просил React + Django REST.

## Стек и структура

```
student-board/
  backend/    Django 5 + DRF + djangorestframework-simplejwt + django-cors-headers
  frontend/   React 18 + Vite + TypeScript, react-router, react-i18next, @dnd-kit, axios
  docs/
```

- БД: SQLite по умолчанию; PostgreSQL через переменную окружения `DATABASE_URL` (опционально, решение исполнителя).
- Часовой пояс: `Asia/Bishkek` — от него считаются «сегодня» и стрик.
- Стили: свой CSS с CSS-переменными (без UI-библиотек), чтобы точно повторить вид LMS. Тема — атрибут `data-theme` на `<html>`.
- Переводы: `frontend/src/i18n/{ru,en,ky}.json`. Кыргызский пишет исполнитель; пометить в README, что его стоит вычитать носителю.
- Выбор темы и языка хранится в `localStorage`. По умолчанию: тёмная тема, русский язык.

## Роли и потоки

- `Group` (поток) — создаётся только в админке Django.
- Пользователь регистрируется сам: логин, пароль, имя, фамилия, роль (*студент* / *преподаватель*). Студент обязан выбрать поток из списка; у преподавателя потока нет.
- Студент: ведёт свою доску и дейлики. По умолчанию видит свой поток, но может переключиться на любой (смотреть может кто угодно).
- Преподаватель: только читает. У него нет своей доски, дейликов, стрика. Видит переключатель потоков; по умолчанию — первый поток по алфавиту.
- Анонимный пользователь видит только страницы входа/регистрации.
- Менять карточку или дейлик может только автор.

## Данные

```
User (кастомный, AbstractUser)
  first_name, last_name, username, password
  role: student | teacher
  group: FK Group, null для teacher

Group
  name (уникальное)

Task
  owner: FK User (только student)
  title (≤ 200), description (текст, опционально)
  status: todo | in_progress | done
  position: int — порядок внутри колонки владельца
  created_at, updated_at

Daily
  author: FK User (только student)
  date: дата (Asia/Bishkek), unique (author, date)
  done: текст — «что сделал» (обязательно)
  plans: текст — «что планирую» (опционально)
  blockers: текст — «что мешает» (опционально)
  tasks: M2M Task — карточки, о которых дейлик (только свои)
  created_at, updated_at
```

Поле `done/plans/blockers` — решение исполнителя (формат стендапа); заказчик сказал лишь «описать свою работу».

## Правила

- **Дейлик**: один на студента в день. Создаётся только на сегодня. Редактировать/удалять — только автор и только в день создания.
- **Карточка**: автор может создавать, редактировать, удалять, перемещать между колонками и менять порядок в любое время.
- **Стрик**: число последовательных учебных дней с дейликом, заканчивающихся сегодня (или вчерашним учебным днём, если сегодня дейлика ещё нет). Учебная неделя — пн–сб, как на скриншоте; воскресенье стрик не обрывает и не прибавляет. Если пропущен учебный день — стрик 0. (Решение исполнителя.)
- **Воскресенье**: дейлик писать можно, он виден в ленте как обычный, но в стрике не учитывается. В воскресенье полоска показывает только что закончившуюся неделю (пн–сб). (Решение исполнителя.)
- **Недельная полоска стрика** на главной: пн–сб текущей недели, огонёк «горит» в дни, когда дейлик есть; сегодняшний день подсвечен красным, как на скриншоте.

## API (DRF, префикс `/api/`)

```
POST   auth/register/              → создать пользователя, вернуть токены
POST   auth/token/                 → access + refresh
POST   auth/token/refresh/
GET    auth/me/                    → текущий пользователь (+ streak для студента)

GET    groups/                     → список потоков (доступен и без входа — для формы регистрации)
GET    groups/{id}/students/       → студенты потока

GET    tasks/?group=&owner=        → карточки (фильтры), отсортированы по status, position
POST   tasks/                      → создать (автор = текущий, status по умолчанию todo, в конец колонки)
PATCH  tasks/{id}/                 → изменить поля
DELETE tasks/{id}/
POST   tasks/{id}/move/            → {status, position} — перенос с пересчётом position у соседей

GET    dailies/?group=&author=&date= → лента, новые сверху, пагинация по 20
POST   dailies/                    → создать на сегодня
PATCH  dailies/{id}/
DELETE dailies/{id}/
GET    dailies/today/              → мой сегодняшний дейлик или 404

GET    users/{id}/                 → профиль: имя, роль, поток, streak, неделя стрика
```

Язык ошибок сервера: фронт шлёт `Accept-Language` (ru/en/ky) в каждом запросе, в Django включён `LocaleMiddleware` и `LANGUAGES = ru, en, ky`. Встроенные сообщения Django/DRF/simplejwt придут на выбранном языке там, где у них есть перевод; для недостающих кыргызских строк — свой `locale/ky/LC_MESSAGES/django.po` только для сообщений, которые реально видны в формах (вход, регистрация, дейлик). (Решение исполнителя.)

Ответы содержат автора в виде `{id, first_name, last_name, initials}`, чтобы фронт рисовал аватар-инициалы («ВВ») без лишних запросов. Ошибки валидации — стандартный формат DRF; фронт показывает их как есть, а свои тексты переводит через i18n.

Права: всё кроме `register`, `token*`, `groups/` требует входа. Изменение/удаление — `IsOwner`. Создание задач и дейликов — только роль student.

## Страницы (frontend)

Общий каркас: боковое меню (лого «Student Board», пункты), верхняя панель справа: имя, переключатель темы (☀/🌙), переключатель языка (RU | EN | KY), выход. На узких экранах меню сворачивается в бургер.

Меню студента: **Главная, Доска, Дейлики, Профиль**. Меню преподавателя: **Доска, Дейлики** (главная у него — доска).

1. **Вход / Регистрация** — отдельные страницы без меню; переключатели темы/языка тоже есть.
2. **Главная** (студент)
   - Шапка: инициалы, ФИО, поток.
   - Карточка стрика: «🔥 N дней подряд», полоска пн–сб, «сегодня, 27 ноября». Если сегодня дейлика нет — кнопка «Написать дейлик».
   - «Мои задачи в работе» — список карточек `in_progress`, стрелка ведёт на доску.
   - «Свежие дейлики потока» — 5 последних, стрелка ведёт в ленту.
3. **Доска** — сверху переключатель потока (у преподавателя всегда, у студента тоже), фильтр «все студенты / конкретный». Три колонки. Карточка: заголовок, инициалы и имя владельца. Свои карточки можно перетаскивать (dnd-kit) и открывать на редактирование; чужие — открываются только на просмотр. Кнопка «+ Задача» в колонке «Планирую» (только студенту и только на своём потоке).
4. **Дейлики** — переключатель потока, фильтр по студенту, лента. Элемент ленты: автор, дата, три блока текста, чипы связанных карточек. Студенту — кнопка «Написать дейлик» (или «Редактировать сегодняшний»). Форма: три текстовых поля + мультивыбор своих карточек.
5. **Профиль** (`/users/:id`) — шапка с ФИО, потоком, стриком; вкладки-пилюли «Доска» / «Дейлики» только этого пользователя. Свой профиль — по пункту меню; чужой — по клику на имя где угодно.

Двухколоночная ширина на десктопе: доска — исключение из узкой колонки, она занимает ширину контента (три колонки рядом), остальное — узкая колонка как в LMS.

## Тема

CSS-переменные: `--bg`, `--surface`, `--surface-2`, `--text`, `--text-muted`, `--accent` (красный), `--success` (салатовый бейдж «СДАНО» со скриншота — для колонки «Готово»), `--border`. Тёмная тема снята со скриншотов; светлая — те же формы, светлый фон (#F5F5F7-подобный), белые карточки, тот же акцент.

## Проверка

- Backend: тесты Django/DRF на права (чужое не редактируется, учитель не создаёт), уникальность дейлика в день, правило «редактировать только сегодня», расчёт стрика (включая воскресенье и пропуск), перенос карточки.
- Frontend: Vitest на расчёт/отображение мелкой логики при необходимости; основная проверка — ручной прогон в браузере (обе темы, три языка) и скриншоты Playwright.
- README: как запустить бэк и фронт, как создать потоки в админке, `createsuperuser`.
